# 市場規模の出典台帳 仕様書（初版）

- 作成日: 2026-10-22
- 状態: 初版（未決事項は §11）
- 対象外: 見た目のデザイン（配色・タイポグラフィ・レイアウト）は別途決める

---

## 1. 目的

一つの市場について、出典ごとにバラバラな「市場規模」の数字を、**定義と一緒に**並べて見られるようにする。

- 同じ年の同じ市場でも、数え方（出荷か小売か、国内生産だけか輸入を含むか、年度か暦年か）で数字は倍以上変わる。
- その違いを一目で見える形にし、引用するときに取り違えないようにする。
- 調べるたびにデータを1行足すだけで台帳が育ち、市場を増やしても同じ仕組みで使えるようにする。

## 2. 基本ルール（台帳の書き方）

1. **1つの数字 = 1行。** 1つの記事に5つの数字があれば5行になる。
2. **数字は必ず「誰が・何ベースで・どの期間か」とセットで書く。** 定義が分からない項目は空欄にせず `unknown` / `null` と明記する。
3. **確認したことだけ書く。** 原典の文面で確認した数字は `verified`、ニュース記事やまとめサイト経由でしか見ていない数字は `unverified` とする。推測で埋めない。
4. **原典と経由先を分けて記録する。** 数字を作ったのは誰か（`source`）と、自分がどこで読んだか（`via`）を別の項目にする。
5. **計算で出せる値は保存しない。** 前年比・構成比・倍率は画面側で計算する。保存するのは原典に書かれた絶対値だけ。
6. **古い数字も消さない。** 予測が実績に置き換わっても、両方の行を残す（改訂の履歴になる）。

## 3. 構成

ビルド工程なしの静的サイト（HTML / CSS / JS / JSON）。GitHub Pages で配信できる形にする。

```
/
├─ index.html              市場一覧
├─ market.html             市場ページ（market.html?id=cosmetics-jp）
├─ sources.html            出典カタログ
├─ glossary.html           用語集（年度と暦年、出荷と小売 など）
├─ css/
├─ js/
│   ├─ load.js             データ読み込み（JSON / JSONL のパース、ID解決）
│   ├─ view-range.js       「定義の幅」グラフ
│   ├─ view-series.js      時系列グラフ
│   ├─ view-matrix.js      定義マトリクス
│   └─ view-table.js       一覧表・フィルタ
├─ data/
│   ├─ markets.json        市場とセグメントの定義
│   ├─ sources.json        出典カタログ
│   └─ observations/
│       └─ cosmetics-jp.jsonl   数字の台帳（市場ごとに1ファイル）
├─ tools/
│   └─ validate.mjs        データ検証スクリプト（Node）
└─ .github/workflows/
    └─ validate.yml        push 時に validate を実行
```

- 数字の台帳は **JSON Lines（.jsonl）** にする。1行が1つのJSONオブジェクトなので、「1行足す」がそのままファイル操作になり、Git の差分も1行単位で読める。
- `file://` で開くとブラウザがデータ読み込みを止めるので、手元で見るときは簡易サーバーを使う（`npx serve` など）。

## 4. データモデル

### 4.1 markets.json — 市場の定義

```json
{
  "id": "cosmetics-jp",
  "name": "化粧品（日本）",
  "geo": "JP",
  "segments": [
    { "id": "total",    "name": "全体" },
    { "id": "skincare", "name": "スキンケア", "parent": "total" },
    { "id": "oem",      "name": "受託製造（OEM）", "related": true }
  ],
  "scope_flags": [
    { "id": "imports",     "label": "輸入品を含む" },
    { "id": "quasi_drugs", "label": "医薬部外品を含む" }
  ],
  "note": ""
}
```

| 項目 | 必須 | 内容 |
|---|---|---|
| `id` | ○ | 市場ID。observations のファイル名と一致させる |
| `name` | ○ | 表示名 |
| `geo` | ○ | 地域コード（JP など） |
| `segments` | ○ | セグメントの一覧。`parent` で階層、`related: true` は市場規模そのものではない関連指標（輸出入、OEM など） |
| `scope_flags` | ○ | この市場で定義を分ける判断材料になる「含む／含まない」の項目。市場ごとに決める |
| `note` |  | 市場全体についてのメモ |

### 4.2 sources.json — 出典カタログ

```json
{
  "id": "yano-2026-cosmetics",
  "publisher": "矢野経済研究所",
  "title": "化粧品市場に関する調査を実施（2026年）",
  "published": "2026-10-16",
  "url": "https://www.yano.co.jp/press-release/show/press_id/4207",
  "type": "research_firm",
  "access": "free_summary",
  "license": "restricted",
  "note": ""
}
```

| 項目 | 必須 | 内容 |
|---|---|---|
| `id` | ○ | 出典ID（発行元-年-テーマ の形を推奨） |
| `publisher` | ○ | 発行元 |
| `title` | ○ | 資料名・記事名 |
| `published` |  | 発行日（YYYY-MM-DD）。不明なら `null` |
| `url` |  | URL。未取得なら `null` |
| `type` | ○ | 出典の種類（§4.4） |
| `access` | ○ | 入手性（§4.4） |
| `license` | ○ | 再利用の可否（§4.4）。公開時の表示ルールに使う（§9） |
| `note` |  | 定義・注意点・原資料名など |

### 4.3 observations/{market}.jsonl — 数字の台帳

1行の例:

```json
{"market":"cosmetics-jp","segment":"total","period":"2025","period_type":"FY","status":"actual","basis":"maker_shipment","value":26430,"unit":"oku_yen","scope":{"imports":true,"quasi_drugs":true},"source":"yano-2026-cosmetics","via":null,"check":"verified","retrieved":"2026-10-22","note":""}
```

| 項目 | 必須 | 内容 |
|---|---|---|
| `market` | ○ | 市場ID |
| `segment` | ○ | セグメントID |
| `period` | ○ | 期間（年なら `"2025"`。四半期・月を扱うときは `"2025-Q1"` `"2025-04"`） |
| `period_type` | ○ | 年度か暦年か（§4.4） |
| `status` | ○ | 実績・速報・推計・予測（§4.4） |
| `basis` | ○ | 何ベースの数字か（§4.4） |
| `value` | ○ | 原典に書かれた値（数値） |
| `unit` | ○ | 単位（§4.4） |
| `scope` | ○ | 市場の `scope_flags` ごとの `true` / `false` / `null`（不明）。書かない項目は不明扱い |
| `source` | ○ | 数字を作った原典の出典ID。原典が分からないときは `"unknown"` |
| `via` | ○ | 自分が数字を読んだ経由先の出典ID。原典で直接読んだなら `null` |
| `check` | ○ | 確認状態（§4.4） |
| `retrieved` | ○ | 取得日（YYYY-MM-DD） |
| `note` |  | 原文の補足（「約」付きの数字、比率の注記など） |

### 4.4 列挙値

**period_type**

| 値 | 意味 |
|---|---|
| `FY` | 4月〜翌3月の年度 |
| `CY` | 1月〜12月の暦年 |
| `FY_other` | それ以外の年度・決算期（`note` に期間を書く） |
| `unknown` | 不明 |

**status**

| 値 | 意味 |
|---|---|
| `actual` | 実績 |
| `preliminary` | 速報値 |
| `estimate` | 推計（実績期間についての見込み） |
| `forecast` | 予測（将来期間） |

**basis**

| 値 | 表示名 | 意味 |
|---|---|---|
| `maker_shipment` | ブランドメーカー出荷額 | ブランドを持つメーカーの出荷金額 |
| `production_shipment` | 国内生産の出荷額 | 国内工場で生産された分の出荷金額 |
| `retail` | 小売・購入額 | 消費者が支払った金額に近い数え方 |
| `business_revenue` | 事業者売上高 | 対象事業者の売上の合計（OEM など） |
| `trade_export` | 輸出額 | 貿易統計の輸出 |
| `trade_import` | 輸入額 | 貿易統計の輸入 |
| `unknown` | 不明 | 原典で定義を確認できていない |

**unit**

| 値 | 表示 | 億円換算 |
|---|---|---|
| `oku_yen` | 億円 | 1 |
| `million_yen` | 百万円 | 0.01 |
| `yen` | 円 | 0.00000001 |
| `million_usd` | 百万ドル | 換算しない（別軸で表示） |

**check**

| 値 | 意味 |
|---|---|
| `verified` | 原典の文面で数字を確認した |
| `unverified` | 経由先でしか確認していない |
| `doubtful` | 年・定義・原典のいずれかに疑問がある |

**source.type**: `government` / `association` / `research_firm` / `company_ir` / `media` / `aggregator`
**source.access**: `free` / `free_summary`（要約のみ無料） / `paid`
**source.license**: `open`（出典明記で再利用可） / `restricted`（転載に許諾が必要） / `unknown`

## 5. 画面

### 5.1 市場一覧（index.html）

市場ごとのカードを並べる。各カードには次を出す。

- 市場名
- 最新年の「全体」の幅（最小〜最大。例: 1兆3,745億〜3兆2,246億円）
- 出典数・行数
- 要確認の行数
- 最終更新日（`retrieved` の最大値）

### 5.2 市場ページ（market.html?id=…）

上から順に次のビューを置く。

1. **定義の幅**: セグメントと年を選ぶと、その年の数字を出典ごとに棒で並べる。棒は値の小さい順に並べ、`basis` で色分けし、ラベルに出典名・`period_type`・`scope` を添える。この台帳の中心になる画面。
2. **時系列**: 系列（§6-1）ごとの線グラフ。実績は実線、予測は破線、速報は白抜きの点にする。
3. **定義マトリクス**: 行が系列、列が `basis` / `period_type` / 各 `scope_flags`。✓ / ✗ / ? で埋める。どの数字が何を含むかを表で比べる。
4. **一覧表**: 全行を表で出す。セグメント・年・basis・status・check で絞り込める。各行から出典URLへ飛べる。
5. **改訂と不一致**:
   - 改訂: 同じ発行元・同じ期間・同じ定義で、発行日の違う数字（予測 → 実績など）を並べる。
   - 不一致: 同じ原典を名乗るのに、経由先によって値が違う数字を並べる。
6. **要確認リスト**: `check` が `unverified` / `doubtful` の行と、`source: "unknown"` の行を一覧にする。次に原典を当たる対象。

### 5.3 出典カタログ（sources.html）

出典を `type` ごとにまとめた一覧。発行元・資料名・発行日・入手性・再利用可否・その出典を使っている行数を出す。

### 5.4 用語集（glossary.html）

年度と暦年、出荷と小売、実績と速報と予測、原典と経由先など、台帳の項目の意味を短く説明する。

## 6. 表示ルール

1. **系列の単位**: 線でつなぐのは `source`・`basis`・`period_type`・`segment`・`scope` がすべて同じ点だけ。定義が違う点どうしは絶対に線で結ばない。
2. **年度と暦年の位置**: 時系列の横軸は連続した時間軸にし、各期間の中心に点を置く。
   - `CY` の2024 → 2024年7月1日の位置
   - `FY` の2024（2024年4月〜2025年3月）→ 2024年10月1日の位置
   - `FY_other` / `unknown` は暦年の位置に置き、点に「?」を付ける
3. **改訂**: 同じ系列・同じ期間に複数の行があるときは、発行日の新しい行を標準表示にし、古い行は薄く表示する。
4. **確認状態**: `unverified` には「未確認」、`doubtful` には「要確認」のバッジを付ける。`via` がある行には「経由: ○○」と出す。
5. **単位**: 表示は億円にそろえ、大きい数字は「2兆6,430億円」の形で書く。ドル建ての数字は円に換算せず、別の軸で表示する。
6. **計算値**: 前年比・倍率・構成比は画面で計算し、計算値であることが分かる表示にする。

## 7. 検証（tools/validate.mjs）

push のたびに GitHub Actions で実行する。

**エラー（止める）**
- 必須項目の欠け
- 列挙値が定義にない
- `market` / `segment` / `source` / `via` の ID が定義にない（`source` の `"unknown"` は可）
- `source` が `"unknown"` なのに `check` が `verified`
- `value` が数値でない
- `scope` に市場の `scope_flags` にない項目がある
- 日付が YYYY-MM-DD でない
- 完全な重複行（`market`・`segment`・`period`・`period_type`・`basis`・`status`・`source`・`via`・`value` がすべて同じ）

**警告（止めずに一覧で出す）**
- 不一致: `market`・`segment`・`period`・`period_type`・`basis`・`status`・`source` が同じで、`via` だけが違い、値が異なる行
- `check` が `unverified` / `doubtful` の行
- `url` が `null` の出典

## 8. 更新手順

### 手で追加する場合

1. 数字の出典が `sources.json` になければ追加する（原典と経由先の両方）。
2. `observations/{market}.jsonl` の末尾に、数字1つにつき1行を足す。
3. `node tools/validate.mjs` を実行する。
4. commit する。

### Claude に頼む場合

「この記事の数字を台帳に追加して: {URL}」と頼む。Claude は次の順で作業する。

1. 記事が原典か経由先かを判定し、原典が特定できればその出典も登録する。
2. 記事に出てくる市場規模の数字をすべて拾い、1数字1行で追記する。
3. 原文で確認できない項目は `unknown` / `null` にし、推測で埋めない。
4. validate を実行する。
5. 追加した行と警告を報告する。

## 9. 公開範囲とデータの権利

- **当面は手元用**として作る。GitHub の公開リポジトリに置くと、画面に出さない数字も JSON ごと誰でも見られる点に注意する。
- 公開版を作るときは、`source` の `license` で表示を分ける。
  - `open`（政府統計など。各サイトの利用規約で出典明記の条件を確認する）: 数字を表示する。
  - `restricted` / `unknown`（調査会社など）: 出典名・期間・定義・リンクだけを表示し、数字は伏せる。たとえば矢野経済研究所は、報道目的以外での引用・転載について広報への問い合わせを求めている。
- 公開版は、元データから `open` の行だけを抜き出すスクリプトで作り、元データは非公開リポジトリに置く。

## 10. 段階的な作り方

1. データファイル（付録A）と `validate.mjs` を置き、市場ページの**一覧表**を出す。
2. **定義の幅**グラフと**定義マトリクス**を作る。
3. **時系列**、**改訂と不一致**、**要確認リスト**を作る。
4. 出典カタログ・市場一覧・用語集を作り、2つ目の市場を追加する。
5. 公開版の抜き出しスクリプトを作る（公開する場合）。

2026-10-22 の調査で拾った数字。原典 URL が未取得の出典は `url: null` にしてある。

初期データの本体は、仕様書の付録Aと同じ内容で次のファイルに置いてある（二重管理を避けるため、ここには再掲しない）。

- `data/markets.json`

### 初期データで見えること

この時点で、台帳の各画面が役に立つ例がそろっている。

- **定義の幅**: 2024年の「全体」が、国内生産の出荷額 1兆3,745億円から小売に近い推計 3兆2,246億円まで、約2.3倍開く。
- **改訂**: 矢野の2025年度は、2025年発表時の予測 2兆6,500億円が、2026年発表の実績で 2兆6,430億円になった。
- **不一致**: 韓国からの輸入額（2024年）が、経由先によって 923億円と約1,342億円に分かれる。どちらも財務省の貿易統計が原典とされているので、化粧品に含める品目の範囲が違う可能性が高い。原典で要確認。
- **基準の違い**: スキンケアは、富士経済の2028年予測（1兆4,896億円）が矢野の2030年度予測（1兆2,600億円）より大きい。先の年の予測のほうが小さいので、集計基準が違う。
- **要確認リスト**: 小売に近い推計（3兆2,246億円）は原典・年・定義が未確認。経産省・財務省の数字はまだ経由先でしか見ていないので、e-Stat と貿易統計の原典で確認すると `verified` に上げられる。
